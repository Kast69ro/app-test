# Требования к бэкенду от мобильного приложения

Мобильное приложение мерчанта (Flutter, iOS + Android, публикация в Google Play и App Store)
работает с текущим `/pos` API (`docs/pos_api_handoff.md`). Ниже — что нужно изменить или
добавить. Возврат платежа — отдельно, в `docs/refund_api_spec.md`.

Приоритеты: **P0** — без этого нельзя выпускать в сторы, **P1** — нужно для следующих экранов,
**P2** — улучшения.

---

## P0. Авторизация токенами вместо `?phone=`

**Проблема.** Сейчас `GET /pos/terminal`, `/pos/summary`, `/pos/history` отдают данные любому,
кто знает номер телефона терминала. Номер — не секрет: зная его, можно читать историю
платежей чужой точки без SMS-кода.

**Что нужно.**
1. `POST /pos/otp/verify` при успехе дополнительно возвращает:
   ```json
   { "access_token": "…", "access_expires_in": 900,
     "refresh_token": "…", "refresh_expires_in": 2592000 }
   ```
2. Все GET-ручки принимают `Authorization: Bearer <access_token>`, терминал определяется
   по токену. Параметр `?phone=` убрать (или игнорировать, когда есть токен).
3. `POST /pos/auth/refresh` `{ "refresh_token": "…" }` → новая пара токенов
   (старый refresh становится недействительным — ротация).
4. `POST /pos/auth/logout` — отзывает refresh-токен. Приложение вызывает его по кнопке «Выйти».
5. Ответ `401` при истёкшем / отозванном токене. На `401` приложение один раз делает refresh;
   если и он `401` — отправляет на вход по SMS.
6. Отзыв всех токенов терминала, если номер отвязали от точки или мерчант отключён.

Срок жизни — на ваше усмотрение; ориентир: access 15 мин, refresh 30 дней.

## P0. Боевой адрес по HTTPS

- Домен шлюза в DMZ для prod-сборки (сейчас известен только тестовый `http://10.64.20.101:8888`).
- Только HTTPS (TLS 1.2+). iOS и Android в prod запрещают http.
- Приложение будет делать certificate pinning — нужен публичный ключ (SPKI SHA-256) сертификата
  и **запасной** ключ на случай перевыпуска, плюс предупреждение заранее о смене сертификата.

## P0. Единый формат ошибок

Сейчас приложение показывает пользователю текст из `detail`. Просьба:
- `detail` — всегда **строка на русском**, понятная мерчанту (не стек, не английский).
- Ошибки валидации (`422`, где `detail` — список) приложение не показывает — для ручек,
  которые вызывает приложение, лучше возвращать `400` со строкой.
- Для `429` дополнительно число секунд до повтора: заголовок `Retry-After` или поле
  `retry_after` — тогда таймер «Отправить код снова» покажет точное время.
- Ограничение частоты (rate limit) на `otp/request` и `otp/verify` по номеру **и** по IP.

## P1. Идентификатор платежа

В `payments[]` и `last_payment` нет ID. Нужен для:
- кнопки «Возврат платежа» (`POST /payments/{id}/refund` из спецификации возврата);
- номера операции в чеке «Поделиться чеком» — без него чек нечем сверить при обращении в банк;
- подгрузки страниц без дублей.

```json
{ "id": "…", "rrn": "…", "sender": "…", "sender_bank_id": 27, "amount": 150.00,
  "status": "success", "creation_datetime": "2026-09-08T14:12:00+05:00" }
```
`rrn` (или иной номер операции из НБТ / банка-отправителя) — если есть, для чека.

## P1. Часовой пояс в датах

`creation_datetime` приходит без часового пояса (`2026-09-08T14:12:00`). Приложение считает его
местным временем телефона. Если телефон в другом поясе — время и группировка по дням поедут.
Просьба отдавать с поясом: `2026-09-08T14:12:00+05:00`.

Для `GET /pos/summary?date=` подтвердить: день считается по времени Душанбе (UTC+5)?

## P1. Пагинация истории без дублей

`offset` сдвигается, когда приходят новые платежи: пока мерчант листает, на следующей странице
появляются дубли. Варианты (любой):
- курсор: `GET /pos/history?before_id=…&limit=50`;
- или `GET /pos/history?to=<время первой загрузки>` — фиксированная граница.

## P1. Единицы сумм

Текущий API отдаёт суммы в **TJS дробным числом** (`150.00`), а `refund_api_spec.md` — в
**дирамах целым** (`125000`). Нужно выбрать одно для всех ручек. Предпочтительно — дирамы
целым числом (нет ошибок округления), но тогда во всех ответах сразу.

## P1. Данные терминала

- `GET /pos/terminal` не возвращает `terminalId` (он есть только в `otp/verify`).
  Добавить в блок `terminal`, чтобы ID обновлялся вместе с остальными данными.
- Список статусов платежа зафиксировать. Сейчас: `success`, `cancel`; позже `refunded`,
  `refund_pending`. Любой другой статус приложение покажет как «Неизвестно».

## P2. Для «Хода операции» в карточке

В карточке операции есть блок «Ход операции» (QR создан → клиент отсканировал → оплачено).
Сейчас у всех шагов одно время — данных нет. Если есть время шагов — отдать в платеже,
иначе блок уберём.

## Не к бэкенду, но нужно от банка

- Адрес страницы **политики конфиденциальности** — обязателен для Google Play и App Store.
- Окончательный ID приложения (сейчас `tj.activbank.activbank_qr`) и аккаунты разработчика
  Google Play / Apple Developer.
