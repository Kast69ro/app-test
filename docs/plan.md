# План: перенос ActivBank QR на Flutter

Правила проекта — в `CLAUDE.md`. Здесь — порядок работ, опись UI из прототипа
и открытые вопросы. Эталон UI — `POS Terminal.dc.html` (строки указаны ниже).

## Как устроена работа
- Flutter SDK стоит локально (`D:\dev\flutter`): `dart format`, `flutter analyze`, `flutter test`
  и предпросмотр в браузере (`flutter run -d chrome --flavor dev -t lib/main_dev.dart`, только вёрстка).
- APK / AAB / IPA собираются в GitHub Actions. Android SDK и Xcode локально не нужны.
- Прототип (`POS Terminal.dc.html`, `*.js`, `assets/`) не удаляем, пока Flutter-версия
  не догонит прототип. Потом — в `legacy/`.

## Этапы

### 0. Каркас — сделано (2026-10-18), кроме iOS
Сделано: проект в `app/`, пакеты, шрифты, l10n, `main_dev` / `main_prod`, CI (analyze + test + dev APK),
Android `productFlavors` dev/prod, http только в dev к 10.64.20.101, `INTERNET` в основном манифесте,
бэкап запрещён. Папка `web/` — только для предпросмотра вёрстки в браузере, в сторы не идёт.
Не сделано: iOS-схемы dev/prod (нужен Mac или CI на macOS).
- `flutter create` (org — см. вопросы), flavors `dev` / `prod`, `main_dev.dart` / `main_prod.dart`, `env.dart`.
- Пакеты из `CLAUDE.md`, `build_runner` для freezed / riverpod.
- Шрифты IBM Plex Mono (400/500/600) и Lato (400/700) кладём файлами в `assets/fonts/`
  (лицензия OFL). Пакет `google_fonts` не берём: он качает шрифты из интернета при запуске.
- Workflow `.github/workflows/flutter.yml`: format-check, analyze, test, сборка dev-APK как артефакт.

### 1. core — сделано: theme, api, storage, utils, PIN-хеш, общие виджеты + тесты
- `theme/`: цвета и стили текста из таблицы ниже.
- `api/ApiClient` на dio: base URL из env, таймаут 8 с, интерсептор авторизации
  (сейчас добавляет `?phone=`, потом `Authorization: Bearer`), разбор ошибок в `ApiException(code, detail)`.
  Нет сети / таймаут → отдельный тип ошибки для экрана «Повторить».
- `storage/`: обёртка над `flutter_secure_storage` (сессия, данные точки, счётчик попыток PIN).
- `security/`: проверка PIN (соль + PBKDF2 / хеш с солью, не простой хеш как в прототипе), автоблокировка, `FLAG_SECURE`.
- `utils/`: `formatMoney`, `plural` (платёж/платежа/платежей), `dayLabel` (Сегодня / Вчера / «5 мая»),
  маска телефона. **Тесты обязательны.**
- `widgets/`: карточка, кнопка, цифровая клавиатура 3×4 (общая для входа и PIN), чип статуса, блок ошибки.

### 2–3. auth и pin — сделано (2026-10-18)
Вход, код доступа, редиректы роутера, автоблокировка через 30 с в фоне. Тесты: репозитории,
поток сессии, виджет-тест входа на экране 320×568 с шрифтом 1,3×.
Осталось: блокировка по бездействию, `FLAG_SECURE` (этап «Релиз/безопасность»), Face ID / отпечаток (опционально).

### 2. auth — вход (прототип стр. 213–267, логика 906–976)
Телефон 9 цифр со своей клавиатурой → `otp/request` → 6 ячеек кода, автоотправка на 6-й цифре,
«Изменить номер», «Отправить код снова» / «Код снова через N с». Тексты ошибок 404/403/429/400 — как в прототипе.

### 3. pin — код доступа (стр. 176–211, логика 657–705)
Стадии create → confirm → unlock. 4 точки, клавиатура, «Выйти» с подтверждением (вместо «Забыли код?» из прототипа — решение 2026-10-18).
5 ошибок → стереть сессию, на вход по OTP. go_router редиректит по состоянию сессии.

### 4. home — сделано (2026-10-18)
Главная, QR на весь экран (яркость, экран не гаснет), вкладки внизу, «потянуть — обновить».
QR и данные точки кешируются в сессии: QR виден без сети, ошибка — плашкой с «Повторить».
Плитка «Возврат за сегодня» — прочерк, пока бэк не отдаёт `refunded` (отклонённые туда не подставляем).
Riverpod: авто-повтор запросов отключён (`noRetry` в `bootstrap.dart`), иначе ошибка не видна.
Вопрос бэку: в `refund_api_spec.md` суммы в дирамах, а текущий API отдаёт TJS дробным числом.

### 4. home — главная (стр. 26–75) и полноэкранный QR (стр. 122–133)
Шапка, карточка QR (`qr_flutter`, уровень L, тихая зона 4 модуля), плитки, «Последний платёж»
(тап → История). Полный экран: яркость на максимум, экран не гаснет, тап — закрыть.

### 5. history — сделано (2026-10-19)
Группы по дням (сумма оплаченных среди загруженных — как в прототипе), pull-to-refresh,
кнопка «Показать ещё (N)», пустое состояние, ошибка плашкой без потери списка.
Новые платежи между страницами не дают дублей: `offset` сдвигается на рост `total` (`HistoryFeed`).
Осталось: авто-обновление (в прототипе опрос по таймеру).
Вопрос бэку: у платежа нет `id` — для карточки операции и надёжной подгрузки нужен уникальный ID.

### 5. history — история (стр. 77–111)
Группы по дням с суммой успешных за день, `RefreshIndicator`, подгрузка `offset += limit`
(в прототипе кнопка «Показать ещё (N)» — оставляем её), пустое состояние.

### 6. payment + receipt — сделано (2026-10-19)
Карточка поверх вкладок (`/history/payment`, платёж через `extra` — ID у платежа нет).
Реквизиты, «Ход операции» как в прототипе, «Возврат платежа» неактивна.
«Поделиться чеком» только для `success`: `ReceiptView` отрисован под экраном →
`RepaintBoundary.toImage` → PNG в `temp/receipts/` (папка чистится перед каждым чеком) → `share_plus`.
Проверить на устройстве: окно «Поделиться» на Android и iPad (`sharePositionOrigin`).

### 6. payment + receipt — карточка операции (стр. 135–174)
Шапка с суммой и статусом, реквизиты, «Ход операции», «Возврат платежа» (disabled),
вместо «Печать чека» — «Поделиться чеком» (только `success`): PNG через `RepaintBoundary` → `share_plus`.

### 7. settings — сделано частично (2026-10-18)
Открывается тапом по логотипу на главной (вкладок по-прежнему две, как в прототипе).
Есть: данные точки, «Сменить код входа» (текущий → новый → повторить; ошибки в общий счётчик 5),
«Выйти» с подтверждением. Нет: политика конфиденциальности (нужны `url_launcher` и адрес страницы),
версия (нужен `package_info_plus`) — ждут согласования.

### 7. settings — новый экран (в прототипе его нет)
Данные точки, сменить код, политика конфиденциальности, версия, «Выйти».

## Расхождения прототипа и CLAUDE.md — нужно решение
1. **Валюта.** CLAUDE.md: «валюту в UI не пишем». В прототипе «TJS» убран только в плитках,
   а в истории, карточке операции и «Последнем платеже» он есть. Предлагаю убрать везде.
2. **Фон** `#F4F4F2` (прототип) или `#F4F4F1` (CLAUDE.md). Разница незаметна, предлагаю `#F4F4F2` как в прототипе.
3. **Где «Настройки».** В прототипе 2 вкладки. Варианты: третья вкладка или иконка в шапке главной.
4. **Неизвестный статус.** Прототип показывает любой незнакомый статус как «Оплачено» — для банка это опасно.
   Предлагаю показывать нейтрально («Неизвестно», серый) и не давать делиться чеком.
5. **«Ход операции».** Сейчас три строки с одинаковым временем и без данных с бэка. Оставить как есть или убрать?
6. **ID приложения** (`applicationId` / Bundle ID), например `tj.activbank.qr`. Нужно до этапа 0, потом не меняется.
7. **Терминалы Sunmi.** Flutter-версия печать не поддерживает. Старый APK на терминалах продолжает работать отдельно?
