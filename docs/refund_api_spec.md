# Возврат платежа — что нужно от бэкенда

В тестовой сборке (`app-qr-test`, flavor `dev`) возврат уже сделан как **концепт**
(`RefundMode.concept` в `lib/app/env.dart`): весь сценарий работает, но возврат
запоминается только в памяти телефона до перезапуска, на сервер ничего не уходит.
На экране возврата есть плашка «Демонстрация…». В prod возврат выключен
(`RefundMode.off`): кнопка «Возврат платежа» неактивна.

Когда появятся ручки ниже, переключаем `refunds: RefundMode.api`. Код для этого
режима уже готов (`ApiRefundRepository`), менять экраны не нужно.

## Сценарий в приложении
1. Карточка операции → «Возврат платежа» (только у оплаченных и частично возвращённых).
2. Сумма: по умолчанию весь остаток, можно ввести меньше (частичный возврат).
   Причина — необязательное поле, до 120 символов.
3. Подтверждение кодом входа (4 цифры, общий счётчик 5 попыток с экраном входа).
4. Запрос → «Возврат оформлен» (или «Банк обрабатывает возврат»).
5. Платёж можно вернуть несколькими частями, пока сумма возвратов не станет
   равной сумме платежа. Потом кнопка пропадает.

## 1. ID платежа (обязательно)
Без него возврат сделать нельзя: в `payments[]` и `last_payment` нужно поле `id`
(см. P1 в `backend_requirements.md`). Пока `id` нет, в режиме `api` кнопка неактивна.

## 2. `POST /pos/payments/{id}/refund`

Запрос:
```json
{ "amount": 30.50, "reason": "клиент вернул товар" }
```
- `amount` — сумма возврата, **в TJS**, как все суммы текущего API.
  Если решим перейти на дирамы целым числом — сразу во всех ручках (P1 «Единицы сумм»).
- `reason` — необязательно, без него поле не отправляется.

Ответ `200`:
```json
{
  "status": "refunded",
  "refund_id": "…",
  "refunded_at": "2026-09-12T10:24:00+05:00",
  "amount": 30.50
}
```
- `status`: `refunded` — деньги ушли; `pending` — банк обрабатывает.
  Отказ (`rejected`) — не `200`, а ошибка с `detail`.
- Поля в `snake_case`, как в остальном API.

Ошибки: `4xx` со строкой `detail` на русском — приложение показывает её как есть.
Нужны понятные тексты как минимум для случаев:
- сумма больше остатка к возврату (`400`);
- платёж уже возвращён полностью (`409`);
- истёк срок возврата (`400`);
- недостаточно средств на счёте мерчанта (`400`);
- платёж не найден или не этого терминала (`404` / `403`).

Проверки на сервере обязательны, даже если приложение их уже сделало:
сумма > 0, не больше остатка, платёж этого терминала, статус «оплачен».

Идемпотентность: повторный запрос (например, после таймаута) не должен создать
второй возврат. Предлагаем заголовок `Idempotency-Key` — приложение будет
отправлять один и тот же ключ при повторе.

## 3. Платёж после возврата
В `payments[]` и `last_payment`:
```json
{
  "id": "…",
  "amount": 150.00,
  "status": "partially_refunded",
  "refunded_amount": 30.50
}
```
- `partially_refunded` — «Частичный возврат», остаток можно вернуть.
- `refunded` — «Возврат», вернули всё. Если `refunded_amount` не пришёл,
  приложение считает возвращённой всю сумму.
- `refund_pending` — «Возврат в обработке».

Желательно (для «Хода операции»): список возвратов платежа
`refunds: [{refund_id, amount, refunded_at, status}]`.

## 4. Сводка за день
В `GET /pos/summary` блок `refunded` в том же формате, что `success` / `cancel`:
```json
"refunded": { "count": 3, "amount": 1250.00 }
```
`amount` — сумма самих возвратов, а не платежей. Плитка «Возврат за сегодня».

## Открытые вопросы
- Есть ли срок, после которого вернуть нельзя (только сегодня? 30 дней?)
- Можно ли вернуть платёж, который ещё не зачислен мерчанту (в тот же день)?
- Нужен ли чек возврата в «Поделиться чеком»? Если да — какие реквизиты.
- Возврат идёт клиенту в его банк по НБТ — сколько это занимает и что
  показывать, пока `pending`?
