# Возврат платежа — что нужно от бэкенда

Приложение уже содержит три места под возврат. Пока эндпоинтов нет, они
показывают заглушки (сумма берётся из старого блока «отклонённые», кнопка
некликабельна, статуса «возврат» нет).

## 1. Общая сумма возвращённых за сегодня
Плитка на главной, «Возврат за сегодня».

Нужно в существующей сводке за день добавить блок:

```json
{
  "kind": "refunded",
  "amount": 125000,      // в дирамах, как остальные суммы
  "count": 3
}
```

Формат тот же, что у блоков ok / cancelled — тогда фронт читает его без
изменений в парсинге.

## 2. Кнопка «Возврат платежа» в карточке операции
Сейчас кнопка есть, но задисейблена.

Нужно:

`POST /payments/{id}/refund`

Запрос:
```json
{ "amount": 125000, "reason": "по просьбе клиента" }
```
(частичный возврат нужен? если возврат всегда полный — `amount` убираем)

Ответ:
```json
{
  "status": "refunded" | "pending" | "rejected",
  "refundId": "…",
  "refundedAt": "2026-09-12T10:24:00+05:00",
  "amount": 125000
}
```

Ошибки: понятный `code` + `message` на русском — фронт показывает message
пользователю. Отдельно нужны коды для «уже возвращён», «истёк срок
возврата», «недостаточно средств на счёте мерчанта».

Идемпотентность: повторный POST с тем же `id` не должен создавать второй
возврат — возвращать текущее состояние.

## 3. Статус «Возврат» у операции
В списке истории и в карточке.

В объекте платежа нужно поле:
```json
{
  "status": "refunded",
  "refundedAt": "2026-09-12T10:24:00+05:00",
  "refundedAmount": 125000
}
```

Если возврат может быть в обработке — статус `refund_pending`, фронт
покажет его как «Возврат в обработке».

## Открытые вопросы
- Возврат только полный или частичный тоже?
- Есть ли ограничение по времени (например, только за текущий день)?
- Нужно ли подтверждение кодом доступа перед возвратом?
- Печатается ли чек возврата на терминале? (если да — нужен тот же набор
  реквизитов, что у чека платежа)
